Custom B+ Tree Database Engine

PythonB+ treeACIDwrite-ahead log

The idea

A database has two jobs: find rows fast, and survive a crash at the worst possible moment.

A B+ tree handles the first. Each node holds a few sorted keys, and a full node splits and pushes a key upward, so the tree stays short and every lookup takes only a few hops. The write-ahead log handles the second: write what you're about to do in a diary first, then do it. After a crash (the coffee), recovery replays committed transactions and throws away unfinished ones.

My contributions

  • Designed and implemented a B+ tree database engine supporting full CRUD operations with efficient disk storage.
  • Built a table abstraction and database manager on top of the index, with snapshot save and load.
  • Built a transaction manager enforcing ACID properties, with write-ahead logging, locking, commit, rollback and crash recovery.
  • Implemented schema validation and constraints: NOT NULL, UNIQUE, CHECK and foreign-key integrity.
  • Benchmarked the B+ tree against a brute-force baseline and visualised the tree's insertion stages.

Olympia: Sports Management System

FastAPIMySQLJWT · RBACsharding

The idea

Olympia is a web app for running sports events: athletes, teams, matches and results. The drawing follows one request.

It's checked with a JWT, matched against the user's role, and its query lands on one of several shards, picked by hashing the row's key. There's no lookup table to maintain, and the load spreads evenly as the data grows.

My contributions

  • Created a web application with FastAPI and MySQL, including JWT authentication, role-based access control and session management.
  • Added audit logging and tamper detection for sensitive operations.
  • Benchmarked API endpoints with EXPLAIN analysis and optimised query performance with indexing, then load-tested the app.
  • Implemented hash-based database sharding across multiple tables for horizontal scalability and load distribution.

IITGn E-gate: QR-based Campus Access

FlaskMySQLQR codes

The idea

A campus gate that runs on QR codes. Visitors register with the details of a host on campus, and residents simply log in. Both get a QR pass.

At the gate, a guard scans the pass, checks the details that pop up, and the visit is recorded. No paper register required.

My contributions

  • Built a Flask + MySQL campus access system during the HackRush hackathon, with separate journeys for visitors, residents and security guards.
  • Implemented registration and login flows, QR pass generation, and host details for visitors.
  • Built the guards' scanner view and a database of visits to track entries.
